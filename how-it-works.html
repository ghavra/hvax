How BidEyes works

Pre-bid risk review for commercial electrical subcontractors.

You send the bid package. Our pipeline reads it, compares the documents against each other, and returns findings an estimator can check in minutes, each with a citation to the exact page.

IN

ITBs, drawings, specifications, addenda, alternates and the bid form.

OUT

A pre-bid control sheet (priority, issue, source, bid impact, action, owner, status), an addenda delta page, RFI-ready questions, and a citation on every finding. For example: a mismatch between a drawing and a spec section, with the sheet, the section, and the exact wording from each.

Step by step

1. Read and index (our code)

Every page of your package becomes a structured record with its document, page number, sheet number, discipline, spec section and the addendum it came from. We read drawing title blocks and sheet indexes, split specs by section, and OCR scanned pages. Everything goes into a searchable index that combines keyword and semantic search. Any page we cannot read is listed in your report, along with how many pages were reviewed.

2. Map what changed (our code)

Late addenda are where bids go wrong. We compare every addendum against the base package to find which sheets were reissued, which spec sections were replaced, added or deleted, and which alternates or bid-form lines changed. We also link the package together: sheet callouts, spec sections, RFI responses and the sheets they modify. This gives us a map of what is current and what has been superseded.

3. Find candidate risks (our code)

Rules built for electrical work scan the whole package for the things that cost subcontractors money: long-lead equipment, scope-boundary language, drawing and spec numbers that disagree, testing and commissioning requirements, and contract and schedule terms. For each topic, retrieval pulls only the passages that matter, with the relevant addenda attached. Claude never receives the whole package, only a focused set of evidence for each candidate.

4. Claude reviews the evidence (Claude API from Anthropic)

BidEyes uses the Claude API from Anthropic in three roles. A fast Claude model sorts and classifies the candidates. A stronger Claude model reads each evidence set side by side (drawings, specs and addenda) and decides whether they conflict, leave scope unclear, or change the price. It then drafts the finding. Claude must return every finding with an exact quote and a page reference. A finding without evidence is not allowed.

5. Check the evidence (our code and Claude)

Our code confirms that every quote appears word for word on the page it cites. Claims that something is missing from scope are searched for across the whole package and dropped if the item is covered elsewhere. We also check the change map to see whether a later addendum already resolved the issue. Then a separate Claude request tries to disprove each remaining finding. Anything that fails is discarded, and the reason is logged.

6. Estimator review (people)

The founder reviews every high-priority finding before the report is delivered. You receive a short list, with borderline items kept separate. Your estimator checks each citation and makes the final call.

What Claude does and does not do

Claude assists with evidence extraction and drafting. It does not replace estimating judgment, code review, or contractual advice.

BidEyes can miss items and can flag things that turn out not to be issues. That is why every finding carries a citation and is reviewed by a person before it reaches you.

Flags potential risks for estimator review. It does not guarantee that no scope is missed.
